## ครั้งที่ 1: การจัดการโค้ดส่วนเกินและการตรวจสอบความปลอดภัยของ SQL

**ถามอะไร**

สอบถามว่าต้องนำโค้ดจากรูปภาพตัวอย่างที่สอนเรื่องการเขียน SQL ให้ปลอดภัย (เปลี่ยนจาก `${}` เป็น `?`) ไปใส่เพิ่มตรงไหนในไฟล์ `requestService.js` ของตัวเอง

**AI ตอบว่าอย่างไร (สรุปสั้น)**

- AI ตรวจสอบโค้ดให้และแจ้งว่าไม่ต้องใส่เพิ่มแล้ว เพราะฟังก์ชัน `findAll` เขียนได้ปลอดภัยตามหลักการเรียบร้อยแล้ว
- แต่ AI ตรวจพบ Unreachable code (โค้ดที่ไม่มีวันถูกเรียกใช้งาน) ซึ่งก็คือคำสั่ง `db.prepare(...)` ที่ดันไปเขียนต่อท้ายคำสั่ง `return` ทำให้การทำงานซ้ำซ้อนและไร้ประโยชน์ แนะนำให้ลบทิ้งได้เลย

**ใช้ส่วนไหน / แก้เองตรงไหน**

เข้าไปลบบรรทัด `db.prepare('SELECT * FROM requests WHERE status = ?').all(status);` ที่อยู่บรรทัดสุดท้ายของฟังก์ชัน `findAll` ทิ้ง เพื่อให้โค้ดคลีนขึ้น

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2: แก้ปัญหา Terminal พัง (Error: ENOENT: uv_cwd)

**ถามอะไร**

พยายามรันคำสั่ง `npm run dev` แต่โปรแกรมแครชและแจ้งเตือนว่า `Error: ENOENT: no such file or directory, uv_cwd` เกิดจากอะไรและต้องแก้ยังไง

**AI ตอบว่าอย่างไร (สรุปสั้น)**

- อาการนี้เกิดจากการที่โฟลเดอร์ปัจจุบันที่เปิด Terminal ค้างไว้ ถูกลบ เปลี่ยนชื่อ หรือถูกแทนที่ไปแล้ว (เช่น โดนทับจากการดึงโค้ดหรือเปลี่ยน Branch) ทำให้ OS หา Path ปัจจุบันไม่เจอ
- วิธีแก้ไม่ต้องแก้โค้ด แค่ต้อง "รีเฟรช" ตำแหน่งที่อยู่ของ Terminal ใหม่ โดยการพิมพ์ `cd ..` ถอยออกไปแล้ว `cd` กลับเข้ามาใหม่ หรือปิดแล้วเปิด Terminal แท็บใหม่เลย

**ใช้ส่วนไหน / แก้เองตรงไหน**

ปิดแท็บ Terminal ตัวเก่าที่ค้างอยู่ แล้วเปิดใหม่ (หรือใช้คำสั่ง `cd` ถอยเข้าออกใหม่) จากนั้นรัน `npm run dev` อีกครั้ง ระบบก็กลับมาทำงานได้ตามปกติ

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 3: ความแตกต่างของการทดสอบ API ผ่าน Postman กับ PowerShell

**ถามอะไร**

ต้องการทดสอบยิง SQL Injection 3 แบบด้วย Postman ต้องทำอย่างไร และทำไมหน้าจอผลลัพธ์ของเพื่อน (รันผ่าน Terminal) ถึงมีหน้าตาการแสดงผลไม่เหมือนใน Postman

**AI ตอบว่าอย่างไร (สรุปสั้น)**

- หน้าจอของเพื่อนคือการรันใน Windows PowerShell ซึ่งมันจะแปลงคำสั่ง `curl` เป็น `Invoke-WebRequest` ให้อัตโนมัติ ทำให้ผลลัพธ์ถูกแยกส่วนเป็น `StatusCode`, `Content` และ `Headers` อย่างชัดเจน
- หากต้องการทดสอบใน Postman สามารถเอา URL ไปวางได้เลย แต่ถ้าจะกรอกผ่านแท็บ Params ห้ามใส่ `%20` ลงในช่อง Value เพราะ Postman จะทำการเข้ารหัส URL (URL Encoding) ให้อัตโนมัติตอนกด Send ถ้าใส่ไปมันจะกลายเป็นการเข้ารหัสซ้ำซ้อน ให้พิมพ์เว้นวรรคแบบคนปกติได้เลย (เช่น `x' OR '1'='1`)

**ใช้ส่วนไหน / แก้เองตรงไหน**

เปลี่ยนวิธีกรอกข้อมูลในแท็บ Params ของ Postman ใหม่ โดยลบพวก `%20` ออก แล้วพิมพ์เป็นช่องว่างปกติ จากนั้นกดยิงทดสอบจนได้ Status `200 OK` และได้ Body กลับมาเป็น Array ว่าง `[]` ซึ่งพิสูจน์ว่าระบบป้องกัน SQL Injection ได้

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ
