# AI_USAGE — LAB 07

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

> ผู้สอนจะสุ่มถามจากโค้ดที่ส่ง — ถ้าอธิบายไม่ได้ คะแนนส่วนนั้นจะถูกทบทวน

---

## ครั้งที่ 1

**ถามอะไร**
เขียน `AppError` และ `asyncHandler` (ส่วน Challenge) เสร็จแล้ว แต่รันสคริปต์ `check-week07.mjs` ของอาจารย์แล้วติด Error ตัวเช็คงานหาโค้ดไม่เจอ แก้ชื่อไฟล์และย้ายโฟลเดอร์หลายรอบก็ยังไม่ผ่าน

**AI ตอบว่าอย่างไร (สรุปสั้น)**
AI ช่วยวิเคราะห์ว่าสคริปต์ตรวจงานน่าจะสแกนหาเฉพาะในไฟล์ที่มีอยู่แล้ว และไม่ได้สแกนลึกเข้าไปในโฟลเดอร์ `utils` ที่สร้างใหม่ จึงแนะนำให้ย้ายโค้ดทั้งสองตัวไป `export` ไว้ที่ด้านล่างของไฟล์ `middleware/errorHandler.js` แทน

**ใช้ส่วนไหน / แก้เองตรงไหน**
โค้ดฟังก์ชันผมเขียนและทำความเข้าใจเอง แต่ใช้คำแนะนำของ AI ในการย้ายตำแหน่งโค้ดไปรวมในไฟล์ `errorHandler.js` เพื่อให้ระบบสแกนเจอและได้คะแนนครบ

**เข้าใจโค้ดที่ได้มาไหม** ✅ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

---

## ครั้งที่ 2

**ถามอะไร**
ติดปัญหาตอนทำเทสต์เคสและการซ่อน Stack Trace (CP14) ทดสอบยิง API ตอนที่มี Error แล้วระบบยังส่ง Stack Trace กลับมาแบบเต็มๆ ทำให้งงว่าตั้งค่าสลับโหมด Production ตรงไหนผิด

**AI ตอบว่าอย่างไร (สรุปสั้น)**
AI ช่วยชี้เป้าว่าอาจจะลืมเช็คค่า `NODE_ENV` ก่อนส่ง Response และแนะนำวิธีการเขียนดักเงื่อนไขแบบสั้นๆ โดยใช้ `config.isProduction` เพื่อเลือกว่าจะแนบ Stack Trace ไปด้วยหรือไม่

**ใช้ส่วนไหน / แก้เองตรงไหน**
นำหลักการเช็ค `NODE_ENV` ของ AI มาประยุกต์ใช้กับตัวแปรที่ผมเซ็ตอัปไว้แล้วใน `config.js` และนำไปครอบส่วน Response ใน Controller ด้วยตัวเองจนทำงานได้ถูกต้อง

**เข้าใจโค้ดที่ได้มาไหม** ✅ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## สรุป

- **ส่วนที่เขียนเองทั้งหมด:** โครงสร้างหลักของ API (Controllers, Services), โค้ดฝั่ง Frontend React ทั้งหมด, การตั้งค่า `apiClient.js` และการเขียน Test Cases ทั้ง 6 เคสด้วยตัวเอง
- **ส่วนที่ AI ช่วย:** ช่วยหาบั๊ก (Debug) ในจุดที่ใช้เวลาแก้นาน เช่น ปัญหาการหาไฟล์ของสคริปต์ตรวจงานอาจารย์ และช่วยอธิบายลอจิกการซ่อน Stack Trace ตอนติด Error
- **ส่วนที่ยังไม่มั่นใจ:** ไม่มี (ระบบทำงานได้สมบูรณ์)
